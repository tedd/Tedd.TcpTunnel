Embeddable .NET transport · Windows and Linux

TCP tunneling
inside your application.

Tedd.TcpTunnel provides client and server APIs for forwarding or direct duplex streams. Add compression, authenticated encryption, access control, and half-close semantics without delegating application traffic to another process. The project originated to compress and encrypt Microsoft SQL Server (MSSQL) connections.

Transport capabilities

Control the link,
not the application protocol.

Each connection receives independent codec and cipher state. The application continues to read and write its original byte stream.

01

Dual-stack access control

Listen and connect over IPv4 or IPv6. Per-forward ACLs accept exact IP addresses and CIDR subnets, with explicit allow and deny lists.

02

Selectable compression

Select Brotli, LZ4, Zstandard, Deflate, GZip, ZLib, or no compression. Brotli can retain history across frames for repeated data.

03

Authenticated encryption

Encrypt compressed frames with ChaCha20-Poly1305, AES-256-GCM, or AES-256-CCM. Assign a distinct 32-byte shared key to each client.

04

Application TLS termination

Terminate TLS before compression and establish TLS again at the destination. SQL Server support covers TDS 7.x and TDS 8.0 with Encrypt=Strict.

05

Operational host

Run the same transport as named Windows services or systemd units. Structured logs record connection attempts, ACL decisions, retries, failures, and closure.

06

Explicit stream lifecycle

Use full-duplex reads and writes, half-close with CompleteWritesAsync, and deterministic disposal. TCP message boundaries remain application-defined.

Optional Windows host · .NET MAUI

Operate the same transport
outside your process.

The packaged host complements the library. Configure forwards, control a Windows service, and inspect bidirectional throughput without changing the wire protocol.

01

Configure and apply

Edit endpoints, compression, encryption, TLS, ACLs, sockets, logging, and updates. Save validates the configuration before restart or deferred application.

02

Service or tray process

Start, stop, and restart named Windows services, or run the daemon in the application and minimize it to the tray. Telemetry uses a protected local pipe.

03

Inspect and authorize

Compare original and encoded throughput. Preview Windows Firewall rules for listener and peer addresses before applying them.

Engineering constraints

Operate the tunnel
as a security boundary.

Services and logs. Install or remove named Windows services and systemd units from the CLI. JSON-line logs record connection attempts, ACL decisions, establishment, retries, failures, and closure; debug logging adds handshake and exception context. Service commands.

Transport security. Client and server peers can authenticate and encrypt the tunnel with one shared key per client. The protocol does not provide forward secrecy and has not undergone an independent security audit. Disable compression when attacker-controlled data and secrets can occupy one compression context. PCAP captures contain plaintext application data. TLS and SQL Server configuration. Key configuration and revocation.
