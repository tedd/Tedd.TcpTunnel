OPEN SOURCE WINDOWS & LINUX

A TCP tunnel.
At both ends.

Tedd.TcpTunnel forwards TCP connections through a client and server running at opposite ends of a network link. It can compress traffic between them and forwards the original byte stream to your destination service.

TUNNEL OPTIONS

Compression,
batching, and
forwarding.

01 /

Bounded send buffering

Send immediately, or collect data for a maximum number of milliseconds. A full buffer goes out without waiting for the deadline.

02 /

Configurable compression

Choose Brotli, LZ4, Zstandard, Deflate, GZip, ZLib, or no compression. Brotli can retain history across frames to reuse repeated content.

03 /

Multiple forwarding setups

Run independent forwarding setups with their own compression, connection limits, retries, socket settings, and packet captures.

CONFIGURATION

JSON config
or command line.

Every setting is available in JSON and on the command line. Select an example, then set the addresses, ports, and options for your connection.

TERMINAL
tcptunnel --forward app --mode Client
  --listen-port 9000 --remote-host tunnel.example
  --remote-port 9001 --compression Lz4
  --batch-milliseconds 0 --socket:no-delay true

LZ4 with immediate forwarding and TCP_NODELAY. Run a matching Server on the other end.

Updates and security.

GitHub updates. GitHub version checks offer an update. Downloads are verified against release checksums. Portable updates keep the previous binary; installed copies use an installer.

Transport security. TcpTunnel forwards and compresses traffic. It does not encrypt or authenticate the tunnel. Use a trusted network or an encrypted transport such as a VPN.
